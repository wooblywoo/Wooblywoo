A cryptographic source map — like minification, for secrets

SupersCrypt splits storage from visibility. Code is chunked into logical blocks, each independently encrypted with authenticated AES-GCM. A tiny, encrypted manifest maps ciphertext offsets back to real line ranges — so only the blocks that actually changed change.

🧩 Surgical block cryptography

Functional scopes encrypt independently, so pull-request reviews keep their exact green/red line diffs. Only modified blocks move.

🔒 Keys in an isolated vault

Decryption happens exclusively inside a Manifest V3 background service worker. Plaintext never enters the page's JavaScript context — immune to XSS scraping.

⚡ Lazy viewport rendering

The extension reads the manifest and decrypts only the visible rows as you scroll. Even 10,000-line files stay smooth — no main-thread freeze.

Straight answers for security leaders

"Browser extensions expand our attack surface via XSS."

SupersCrypt runs on Manifest V3. Decryption happens exclusively in an isolated background service worker — plaintext and keys never touch the web page's global JavaScript context, making it immune to page-level XSS scraping. For enterprise clients we deliver signed build artifacts you deploy internally via Jamf, Intune or Google Admin, not the public store.

"Decrypting code in the browser will make large files lag."

That was our hardest engineering problem. Because the pre-commit hook pre-chunks and indexes every file, the extension acts like a minification source map: it reads a compact manifest, finds the line ranges currently in the viewport, and lazily decrypts only those DOM nodes as you scroll. Memory footprint stays negligible even on massive files.

"If an endpoint is compromised, can't an attacker just read the screen?"

Correct — screen-scraping malware on an endpoint is a job for your EDR (CrowdStrike, etc.). SupersCrypt neutralizes a different, higher-consequence vector: centralized cloud breaches. Steal a GitHub token today and you get 100% of the IP. With SupersCrypt you get unreadable noise — an attacker would have to breach machines one by one, eliminating the single catastrophic leak.

"Who manages key rotation when an engineer leaves?"

You don't hand-track keys. SupersCrypt integrates with your IdP via SAML/OIDC. When an authorized engineer opens a repo, the extension validates their identity and requests a short-lived, in-memory decryption token. Deactivate them in Okta or Azure AD and their access to both the web UI and any local clone vanishes instantly. Master keys stay governed in your existing enterprise KMS.
